## فرمت داده‌ها

هر ردیف پنج ستون دارد:

| ستون | توضیح |
|---|---|
| `Id` | شناسه ردیف. **بین سال‌ها ثابت نیست**؛ برای اتصال بین سال‌ها از `Code` یا جدول نگاشت استفاده کنید. |
| `ParentCountryDivisionId` | شناسه والد. فقط برای ردیف کشور خالی است. |
| `Name` | نام محل، با کاراکترهای استاندارد فارسی |
| `Code` | کد مرکز آمار |
| `DivisionType` | نوع محل |

### نوع محل در `DivisionType`

| مقدار | نوع | والد |
|---|---|---|
| `0` | کشور | — |
| `1` | استان | کشور |
| `2` | شهرستان | استان |
| `3` | بخش | شهرستان |
| `4` | دهستان | بخش |
| `5` | شهر | بخش |
| `6` | آبادی | دهستان |
| `7` | منطقه شهری | شهر |

⚠️ توجه: `DivisionType` فقط **نوع** محل را نشان می‌دهد، نه **عمق** آن در درخت. تا نسخه ۲ این دو تصادفاً یکی بودند چون شماره‌ها به ترتیب عمق بالا می‌رفتند. با اضافه شدن «منطقه شهری» که زیر شهر قرار می‌گیرد، این رابطه دیگر برقرار نیست. عمق را همیشه از زنجیره `ParentCountryDivisionId` بگیرید. شرط‌هایی مثل `WHERE DivisionType < 5` را بازبینی کنید.

### کدها

- **استان**: دو رقمی، `00` تا `30`
- **شهرستان**: دو رقمی، در هر استان از `01`
- **بخش**: دو رقمی، در هر شهرستان از `01`
- **دهستان**: چهار رقمی، در هر بخش از `0001`
- **شهر و منطقه شهری**: چهار رقمی، در بازه `1001`–`1699` و `2000`–`2999`
- **آبادی**: شش رقمی

کد **شهر و منطقه شهری** و کد **آبادی** در کل کشور یکتا هستند — این را روی داده ۱۴۰۴ بررسی کرده‌ایم (تست در `packages/npm/test/`). به همین دلیل می‌شود یک شهر یا آبادی را بین سال‌ها فقط با کدش دنبال کرد، حتی اگر شهرستان یا بخشش عوض شده باشد. کد بخش و دهستان یکتا نیست و برای آن‌ها به مسیر کامل نیاز دارید.

## مناطق شهری و issue #3

در فایل مرکز آمار، فیلد `coderec = 5` هم شهر و هم منطقه شهری را در بر می‌گیرد و هر دو کد چهار رقمی یکتا می‌گیرند. نتیجه‌اش این بود که «اراک» شش بار در یک بخش تکرار می‌شد:

| کد | نام | نسخه ۲ | نسخه ۳ |
|---|---|---|---|
| `1101` | اراک | شهر | شهر |
| `1678` | اراک ۱ | شهر | منطقه شهری، زیر اراک |
| `1679` | اراک ۲ | شهر | منطقه شهری، زیر اراک |
| `1680` | اراک ۳ | شهر | منطقه شهری، زیر اراک |
| `2858` | اراک ۴ | شهر | منطقه شهری، زیر اراک |
| `2859` | اراک ۵ | شهر | منطقه شهری، زیر اراک |

در نسخه ۳، ۱۹۱ ردیف در ۳۹ شهر (تهران با ۲۲ منطقه، اصفهان ۱۵، مشهد ۱۲ و …) به `DivisionType = 7` تبدیل شدند و والدشان شهر پایه در همان بخش شد. هیچ ردیفی حذف نشده است.

نتیجه: `WHERE DivisionType = 5` فهرست تمیز شهرها را می‌دهد و اگر مناطق را هم بخواهید در `DivisionType = 7` هستند.

تشخیص خودکار انجام می‌شود: نامی که به «فاصله + عدد» ختم شود و شهر هم‌نامی در همان بخش داشته باشد، منطقه شهری است. هر ۱۹۱ ردیف شهر پایه متناظر داشتند.

## یکسان‌سازی کاراکترهای فارسی

فایل مرکز آمار حروف عربی و اعراب و کاراکترهای نامتعارف دارد. در تولید داده این‌ها اصلاح می‌شوند:

| از | به | نمونه |
|---|---|---|
| `ي` `ى` | `ی` | `مرکزي` ← `مرکزی` |
| `ك` | `ک` | `كرمانشاه` ← `کرمانشاه` |
| `أ` `إ` `ة` `ۀ` | `ا` `ا` `ه` `ه` | |
| اعراب و کشیده | حذف | `تهــران` ← `تهران` |
| ارقام فارسی و عربی | ارقام لاتین | |
| نیم‌فاصله بی‌اثر | حذف | `احمد‌آباد` ← `احمدآباد` |

نیم‌فاصله بعد از حرفی که به حرف بعد نمی‌چسبد (`ا د ذ ر ز ژ و` و …) هیچ اثر بصری ندارد و فقط مقایسه رشته‌ها را خراب می‌کند؛ این موارد حذف می‌شوند. نیم‌فاصله‌های معنادار مثل `اسلام‌شهر` دست‌نخورده می‌مانند.

نگارش خود مرکز آمار در برخی نام‌ها ناهماهنگ است (`بندرعباس` و `بندر عباس` هر دو در فایل هستند). این موارد **تغییر داده نشده‌اند**، چون یکسان‌سازی‌شان حدس است نه اصلاح.

</div>

```sql
CREATE DATABASE mydb CHARACTER SET utf8mb4 COLLATE utf8mb4_persian_ci;
```

<div dir="rtl">

نمونه پرس‌وجو — شهرهای استان تهران:

</div>

```sql
SELECT city.Name, county.Name AS County
FROM CountryDivisions city
JOIN CountryDivisions district ON district.Id = city.ParentCountryDivisionId
JOIN CountryDivisions county   ON county.Id   = district.ParentCountryDivisionId
JOIN CountryDivisions province ON province.Id = county.ParentCountryDivisionId
WHERE province.Name = 'تهران' AND city.DivisionType = 5
ORDER BY county.Name, city.Name;
```

## ارتقاء دیتابیس از نسخه ۲ به نسخه ۳

شناسه‌ها بین سال‌ها ثابت نیستند، پس نمی‌شود جدول را ساده جایگزین کرد. `migrations/1398-to-1404/` جدول نگاشت `CountryDivisionIdMap` را می‌سازد تا کلیدهای خارجی خودتان را به‌روز کنید.

</div>

```bash
# ۱) پشتیبان بگیرید
# ۲) جدول قدیمی حفظ و جدول نگاشت ساخته می‌شود
psql -d mydb -f migrations/1398-to-1404/upgrade.sql
# ۳) داده سال ۱۴۰۴ بارگذاری می‌شود
psql -d mydb -f data/1404/iran.sql
# ۴) بخش ۴ فایل upgrade.sql را روی جدول‌های خودتان اجرا کنید
```

<div dir="rtl">

جدول `CountryDivisions_1398` دست‌نخورده باقی می‌ماند تا هر وقت خواستید مقایسه کنید.

ستون `MatchType` می‌گوید نگاشت چقدر قابل اعتماد است:

| `MatchType` | تعداد | معنی |
|---|---|---|
| `path` | ۹۴۴۲۱ | مسیر کدها دست‌نخورده مانده؛ محل جابه‌جا نشده. |
| `code` | ۸۴۷۷ | مسیر عوض شده ولی کد یکتای ملی همان است — محل زیر شهرستان یا بخش تازه‌تشکیل‌شده‌ای رفته. چون کد شهر و آبادی در کل کشور یکتاست، این تطبیق هم قطعی است. |
| خالی | ۹۷۲ | معادلی در ۱۴۰۴ ندارد؛ حذف یا ادغام شده. `NewId` تهی است و تصمیمش با شماست. |

۹۷۲ ردیف بی‌معادل شامل ۷۷۷ آبادی، ۱۵۶ دهستان، ۳۷ بخش و ۲ شهر است. برای بخش و دهستان کد یکتای ملی وجود ندارد، پس وقتی هم مسیر و هم نام عوض شده باشد تطبیق خودکار ممکن نیست.

```js
import { load, DivisionType } from "@hameds/iran-country-divisions";

const ir = load();                       // جدیدترین سال موجود
const tehran = ir.search("تهران", { type: DivisionType.Province })[0];
```

## تعاریف

بر اساس [سند استاندارد آدرس‌دهی مرکز آمار ایران](source/geo_standard.pdf) که در همین مخزن است:

- **استان**: واحدی از تقسیمات کشوری با محدوده جغرافیایی معین که از به هم پیوستن چند شهرستان همجوار با توجه به موقعیت سیاسی، اجتماعی، فرهنگی، اقتصادی و طبیعی تشکیل می‌شود. کشور به ۳۱ استان تقسیم شده است.

- **شهرستان**: واحدی از تقسیمات کشوری با محدوده جغرافیایی معین که از به هم پیوستن چند بخش همجوار که از نظر عوامل طبیعی، اجتماعی، اقتصادی، سیاسی و فرهنگی واحد متناسب و همگنی را به وجود آورده‌اند.

- **بخش**: واحدی از تقسیمات کشوری با محدوده جغرافیایی معین که از به هم پیوستن چند دهستان همجوار مشتمل بر چندین مزرعه، مکان، روستا و احیاناً شهر تشکیل می‌شود.

- **دهستان**: کوچک‌ترین واحد تقسیمات کشوری با محدوده جغرافیایی معین که از به هم پیوستن چند روستا، مکان و مزرعه همجوار تشکیل می‌شود و از لحاظ محیط طبیعی، فرهنگی، اقتصادی و اجتماعی همگن است.

- **شهر**: محلی با حدود قانونی که در محدوده جغرافیایی بخش واقع شده و اکثریت ساکنان دائمی آن در مشاغل کسب، تجارت، صنعت، کشاورزی، خدمات و فعالیت‌های اداری اشتغال دارند، در زمینه خدمات شهری از خودکفایی نسبی برخوردار است و حداقل ده هزار نفر جمعیت دارد.

- **آبادی**: محدوده‌ای واقع در یک دهستان با حدود ثبتی یا عرفی مستقل و خارج از محدوده شهرها یا آبادی دیگر، که به دلیل وجود فعالیت انسان در تمام یا بخشی از آن قابل تشخیص است و معمولاً نام خاصی دارد. آبادی می‌تواند یک ده، یک مزرعه، یک مکان یا یک معدن باشد.

- **منطقه شهری**: بخشی از یک شهر بزرگ که مرکز آمار برای آن کد شهری جداگانه در نظر گرفته است. در فایل مرکز آمار همراه شهرها ثبت می‌شود؛ در این مخزن `DivisionType = 7` دارد و والدش شهر است.

### نگاشت `coderec` مرکز آمار به `DivisionType` این مخزن

| `coderec` | معنی در سند مرکز آمار | `DivisionType` |
|---|---|---|
| `1` | استان | `1` |
| `2` | شهرستان | `2` |
| `3` | بخش | `3` |
| `4` | دهستان | `4` |
| `5` | شهرها و مناطق شهری | `5` یا `7` |
| `6` | آبادی‌های نقطه‌ای | `6` |
| `7` | بلوک‌ها | در فایل سالانه نیست |
| `8` | آبادی‌های دارای نقشه بلوکه | `6` |
| `F` | نقاط فرعی | در فایل سالانه نیست |
| `H` | حوزه | فقط در فایل سرشماری |

ردیف‌های `coderec = 8` هم آبادی هستند و تنها تفاوتشان این است که نقشه بلوکه دارند؛ فیلد `diag` کد چهار رقمی آدرس‌دهی همان آبادی است. این ردیف‌ها مثل نسخه ۲ به عنوان آبادی وارد شده‌اند.
